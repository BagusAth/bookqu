# RF-09 — BOOKING FLOW STABILITY & PRODUCTION HARDENING

## 1. Metadata

**Project:** BookQu
**Branch:** `Refactor`
**Phase:** RF-09
**Type:** Post-Refactor Stability / Bug Fix / Hardening
**Scope:** Customer Booking, Payment, Schedule Availability, Booking Management, Tenant Context, Production Configuration

# 2. Tujuan

RF-09 bukan refactor architecture besar.

RF-00 sampai RF-08 sudah dianggap sebagai baseline architecture. RF-09 bertujuan memperbaiki bug, inkonsistensi behavior, konfigurasi, dan residual technical debt yang ditemukan setelah implementasi RF-08.

Target akhir:

```text
Customer
  ↓
Service
  ↓
Date
  ↓
Time Slot
  ↓
Checkout
  ↓
Payment
  ↓
Booking Confirmation
  ↓
Booking Management
```

harus berjalan konsisten dan menggunakan business rules yang sama.

RF-09 harus memprioritaskan:

1. Correctness
2. Booking integrity
3. Payment integrity
4. Availability consistency
5. Timezone correctness
6. Production reliability
7. Security
8. Regression testing

Jangan melakukan redesign besar atau memindahkan seluruh architecture kembali.

### 2. Gunakan action payment expiry yang sudah tersedia:

```text

sukses
gagal
```

### 4. Pastikan Blade tidak menganggap `kadaluarsa` sebagai database status.

---

```text

    → SUCCESS
```

# P0-04 — SATUKAN DEFINISI ACTIVE / OCCUPIED BOOKING

## Masalah

Saat ini definisi booking aktif tersebar di:

```text
BookingState
BookingRules
AvailabilityRules
GetAvailableSchedules
BookingController
BookingManageController
Schedule model
database constraint
```

Beberapa menggunakan:

```text
pending
paid
completed
```

tetapi pending memiliki grace period 15 menit di sebagian tempat dan tidak di tempat lain.

Ini dapat menyebabkan:

```text
Public availability → AVAILABLE
Reschedule → UNAVAILABLE
CreateBooking → conflict
```

---

## Solusi

Tetapkan satu business definition:

```text
PAID
    → selalu occupied

COMPLETED
    → selalu occupied

PENDING
    → occupied hanya selama payment grace period aktif

CANCELLED
    → tidak occupied
```

Gunakan satu authority.

Rekomendasi:

```text
BookingState::occupiesSlot()
```

menjadi semantic authority.

---

## Implementasi

Refactor `AvailabilityRules` agar menggunakan:

```php
BookingState::occupiesSlot(...)
```

daripada mendefinisikan ulang:

```text
pending > 15 min
pending <= 15 min
paid
completed
```

Pastikan `BookingRules::isSlotOccupied()` juga menggunakan rule yang sama.

Audit:

```text
GetAvailableSchedules
Schedule::getAvailabilityStatus()
BookingController::selectTime()
CreateBooking
RescheduleBooking
CreateWalkInBooking
```

Tidak boleh ada definisi active booking baru.

---

## Acceptance Criteria

Untuk booking:

```text
pending < 15 menit → occupied
pending >= 15 menit → tidak occupied
paid → occupied
completed → occupied
cancelled → available
```

Semua flow harus memberikan hasil yang sama.

# P0-05 — PERBAIKI PENDING EXPIRY + CACHE

## Masalah

Availability dapat menggunakan cache sementara pending booking memiliki expiry/grace period.

Contoh:

```text
10:00 booking pending
10:15 pending expired
10:16 availability masih cache occupied
```

Customer masih dapat melihat slot penuh.

---

## Solusi

Availability cache tidak boleh menjadi source of truth.

Flow wajib:

```text
Cache
 ↓
display optimization

Final booking
 ↓
DB transaction + lock
 ↓
real availability authority
```

Untuk availability query, pending booking harus selalu dihitung menggunakan `BookingState::occupiesSlot()` / equivalent centralized semantics.

---

## Strategi

Gunakan salah satu atau kombinasi:

### Option A — pendekkan TTL availability cache

Gunakan TTL yang lebih pendek dari booking expiry grace.

### Option B — invalidate cache ketika pending booking expire

`ExpirePayment` harus melakukan:

```text
payment expiry
→ cancel booking
→ clear availability cache
```

### Option C — jadikan cache hanya projection

Pastikan `CreateBooking` dan `RescheduleBooking` selalu melakukan final DB validation.

Semua write path WAJIB melakukan final validation.

---

## Acceptance Criteria

```text
[ ] stale cache tidak dapat membuat booking invalid
[ ] expired pending booking kembali tersedia
[ ] CreateBooking tetap melakukan authoritative DB check
[ ] Reschedule melakukan authoritative DB check
[ ] cache di-invalidate setelah expiry
```
